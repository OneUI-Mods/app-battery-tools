# 0.2.0の検証

## 自動テスト

- JVM 49件成功。従来のDigi Police・キャッシュ検証に加え、Wi-Fi切断／復帰、停止中の取り消し、失敗した探索の分離、Bluetoothリセット、保持上限、古いキュー処理と新しい探索の分離、nullableな計算結果、生成中のMatter終了、重複計算と同時要求、閉じたラッパーの同一性を確認。
- Android 16／17のエミュレーターで、実機から取得したWindows・EQ・ECOVACSのAPKに対するDexKit照合が成功。
- 同じWindows APKのSDKクラスを、通信インターフェースだけ模擬して実行。停止後のOnOpenedでクライアントの引き取り先がない状態を再現し、追加の解放処理が1回だけCloseすること、有効なクライアントをCloseしないことを確認。
- WindowsのDB型に、照合したclose経路が一意に存在することを確認。
- 同じEQ APKの識別関数とキャッシュ経由の結果が、複数の出力先で一致することを確認。
- 両エミュレーターで設定UIを起動し、Android 17では全対象カードへのスクロール、ダークモードと文字150%も確認。
- releaseビルドとrelease lintが成功。署名・検証コンポーネント混入チェックは配布パイプラインで行う。

## 実機の状態

署名済みrelease 0.2.0を実機へ更新し、導入APKのSHA-256が公開APKと一致することを確認した。Vectorのスコープは6対象へ追加済み。ユーザーの許可後、稼働していたWindowsにリンクとEarpiece EQだけを再読み込みし、解析ready・フックactive・診断エラーなしを確認した。ほかの対象はその時点で動いていなかったため、次回起動時に読み込まれる。OS／SystemUI／ホームのプロセスは変更していない。

これはフックの初期化確認であり、実際のWi-Fi切り替え、Matter機器、音声出力の比較、長期的な電池削減量の実証は未完了。模擬通信の成功を、端末の全通信経路の検証とは扱わない。

ユーザーの機器を自動解錠・操作する試験や、OS／SystemUI／ホームの再起動は行わない。電池持ちの長期比較と、Windowsの残留した全ネイティブ資源の改善はまだ実証していない。

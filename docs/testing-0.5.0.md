# 0.5.0の検証

JVMテスト93件が成功。新規10件は、実行中の処理を割り込まないこと、予約済み処理の完走、待機後のpoolSize=0、後からの処理を同じexecutorが再開すること、並列数の維持、別ThreadFactory・既存方針・終了済み・null・循環・深すぎる/曖昧なラッパーの拒否、同じ実体を指すフィールドの重複を確認する。

Android 16/17で、従来9本と追加した表示調整APK、さらに実機framework.jarを使い、onClosedと専用executorの生成・所有関係を照合した。Samsungのframeworkをエミュレーターへ置き換えず、解析対象の非公開fixtureとしてのみ使う。

通常のアプリでは非公開Javaフィールドが隠れるため、最初の仮想端末試験ではexecutorの所有者を取得できず、変更が適用されないことを確認した。COWの仮想端末だけhidden_api_policyを変更し、Vectorの信頼されたモジュールからのアクセスに相当する条件で、Android標準Executorsラッパーの展開、待機後のスレッド終了、新しい処理の再開を検証した。Galaxy本体のhidden API設定は変更しない。実機でアクセスできることは別に確認する必要がある。

該当するキューを見つけられないframeworkでは、既存方式へ無理に当てはめず、非適用として結果をキャッシュする。常駐サービス・アラーム・監視タイマーは追加していない。

実機の初期観測と採用理由は[第5回](investigation/system-round5-2026-11-08.md)を参照。実機への反映・対象の再読み込みは操作枠確認後に行う。カメラを開閉しての長時間比較や電池削減量は、この単体・仮想端末試験だけでは実証しない。

13対象の設定画面を両OSで表示し、最後のContinuityまでスクロールできた。Android 17ではダークモード・文字150%を使用し、新規表示調整スイッチのOFF保存・プロセス再起動後の維持・ONへの復元を確認した。

# 検証結果（0.1.0）

## ローカルとエミュレーター

- Kotlin、SDK 37、releaseビルド、release lint、ktfmt/Spotlessを確認。
- JVM 19件成功。設定ON/OFF/不明、サービス実体別の所有権、二重停止、登録完了と停止の順序、解除失敗時の他の登録の解放、初回だけの探索と更新時の探索、同時取得と失敗・中断・破損の終端キャッシュを確認。
- Android 17エミュレーターで3タブ、未導入時の表示、ライセンス一覧とMIT詳細、ダークモードと文字150%を確認。Galaxyの画面操作はしていない。

## Android 17 Galaxyでの比較

Digi Police 3.7.0のエリア通知設定はfalseのまま維持した。画面・設定を操作せず、同じエリアサービスの開始・終了コマンドと対象プロセスの再読み込みで確認した。Rootは検証コマンド用であり、App Battery Tools自身のRoot要求や常駐サービスではない。

| 条件 | エリアサービス | Digi Policeを所有者とするGPS要求 |
| --- | --- | --- |
| アプリ別フックOFF | 起動 | 20秒周期の高精度要求あり |
| 全体フックOFF | 起動 | 同要求あり |
| フックON・エリア通知設定OFF | 停止 | なし |

同一プロセスへの追加の起動要求2回と12秒待機でも、プロセスは継続し、サービスと該当GPS要求が残らなかった。外部起動はアプリ内のContextWrapperを通らないため、純正のforeground準備後の解除・停止もこの試験に含む。

## 自身の待機処理

- 実機のApp Battery ToolsにServiceRecordなし。
- 解析・Binder接続情報取得用のスレッドはアイドル後に不在。
- 約10.2秒のアイドル観測でCPUカウンタ増加0 ticks。端末全体の電池持ちやmAhを測定した結果ではない。
- APK更新後のモジュールプロセスでも探索開始0、保存済み結果readyを確認。初回の探索開始は1。キャッシュはモジュール自身の内部データにある。

## 境界と未検証

kernel boot ID、system_server、SystemUI、One UIホームのPIDとSELinuxを維持した。OS・SystemUI・ホームの再起動、Galaxyの画面操作、音声再生、対象の設定・権限の変更は行っていない。

Android 16の物理端末でのフック動作、エリア通知ONでの長時間の移動と実際のエリア通知受信、地図・着信ブロックの実動作、条件を揃えた長期消費測定は未実施。ONと不明設定を抑止しないことはJVMで確認し、ON側の周期・精度を変更するコードはない。

検証中に見つけたFGSの起動義務違反は修正済み。試行版はGitHub Releaseへ配布せず、連続起動の確認を終えた版を初回配布する。

# 第三者アプリの省電力調査

更新: 2026-11-08。調査を先行し、現在はDigi Police対応の実装・検証を進めています。最新の実機確認結果は開発ドキュメントへ記録します。

## 方針

- 対応機能を1本のApp Battery Toolsへまとめ、アプリごと・改善項目ごとにON/OFFを用意します。
- 小さな改善だけのものは追加しません。消費記録とAPKの両方から、大きな無駄と修正点を説明できるものを優先します。
- 通知・同期・着信処理・位置情報の必要な精度や反応を落として稼ぐ変更は、元の不具合修正と区別します。
- Digi Policeは「エリア通知を受信する」がONの間は従来動作を維持し、OFFで終了した測位の解除漏れを補う方針です。利用者の最新の指定はこちらです。
- Kotlin、libxposed API 102、Android 16/17対応、DexKitによる意味・型・一意性の検証、アプリ別スイッチを予定します。
- DexKit結果はモジュール自身の内部データに保存します。対象APKの初回・更新後だけ再探索し、通常のフックや描画中に全DEX探索を行いません。

## 調べた範囲

ユーザー導入アプリ581件（管理カタログ掲載の自作アプリ18件を含む）の登録情報を取得し、電池統計・アラーム・ジョブ・現在の位置要求・CPU情報から候補を選別しました。これは581件すべてのAPKを逆コンパイルした、という意味ではありません。APKを取得して処理まで精査したのは、現時点ではDigi PoliceとWindowsにリンクの2本です。

電池統計は2026-11-08 02:59開始の約14時間、うち消灯約7時間29分の記録です。アラーム統計はこれと異なる長い期間を含むため、件数を同じ14時間の頻度として扱いません。CPUの短時間値は利用者の操作とADB調査の影響を含み、待機中の定常消費ではありません。

# Digi Police：エリア通知OFF時の測位終了

## 対象

- パッケージ: `jp.co.dawncorp.DigiPolice`
- 調査版: 3.7.0、versionCode 2273
- APK SHA-256: `6fb4df2f2a9665754dc6a2e95af0322f05bd6dd0a014ab2f9517ec962e317baa`
- 方針: エリア通知ON時の要求間隔・優先度・ジオフェンス・着信ブロックを変更しない。OFFにした後の不要な測位だけを終了させる。
- 状態: APK上の解除不足を確認。実機でOFFにした直後の残留再現と修正比較は未実施。モジュールは未実装。

## 実機で確認したこと

- 約14時間の電池使用期間中、GPS利用は約13時間57分、GPSに割り当てられた時間は約13時間50分。
- 取得時点のGPSプロバイダ要求は、このアプリのWorkSourceによる20秒周期・HIGH_ACCURACY。別アプリの一時要求がない場面でも残っていた。
- エリア通知用LocationServiceが実行中だったため、この観測だけでは「OFFなのに残っている」とは断定できない。
- 自プロセスのCPUは約3秒と小さい一方、代理位置処理のウェイクロックやGPSの長時間要求がある。自プロセスのCPUだけで判断してはいけない。

## APKで確認した経路

1. `dawn.plugins.flutter.area_notification.LocationService.onStartCommand` が20秒周期・優先度100のLocationRequestを作成する。
2. 毎回新しいFused Locationクライアントと `U4.b` コールバックを作り、`M2.a.e(LocationRequest, Q2.c, Looper)` に登録する。
3. `U4.b` は通知コールバックの空実装であり、この登録自体はGPSを継続稼働させる役割と考えられる。
4. このサービスはonDestroyを実装しておらず、クライアント・コールバックの参照をフィールドにも保存していない。
5. 通知の終了操作は `ForegroundReceiver.onReceive` からstopServiceだけを呼ぶ。
6. Flutterのエリア通知プラグイン `U4.a.a()` はジオフェンスの解除とstopServiceを行うが、上記コールバックの解除は呼ばない。
7. 同じプラグインの開始処理も、旧サービス停止→新サービス開始を行う。再設定時の古いコールバックが残る可能性もある。
8. Fusedクライアントには `M2.a.d(Q2.c)` という対になる解除メソッドがあるが、上記停止経路では利用されていない。

## 大きな改善になり得る条件

エリア通知OFF後もアプリのプロセスが残り、以前登録したGPS要求が有効なままなら、常時高精度測位を不要な時間だけ止められる。常に節電になると断定せず、GPS所有者とサービスの消失・プロセスの生存をセットで比較する。

ON時の測位を低精度化したり間隔を伸ばす案は採用しない。現在の全体GPS推定値をそのまま削減量としない。

## フックの設計案

- サービス開始処理の範囲内で発生した位置コールバック登録だけを追跡する。地図・現在地ボタン・他の位置プラグインは追跡対象外。
- 実際のクライアントとコールバックをサービス実体に対応付け、サービス終了時に対になる解除を呼び、参照も捨てる。
- 停止→直ちに再開始の順序でも、新サービスのコールバックを誤解除しない。
- ON中の有効な登録を勝手に省略せず、プロセス全体の位置更新を一括で止めない。
- 権限不足・登録失敗・二重停止・解除失敗・初期化途中の停止を扱い、フック側の例外をアプリへ漏らさない。
- フックはアプリ別スイッチで無効化可能にする。対応が証明できない更新版では、推測で解除せずその機能を停止して表示する。

## DexKitの記録案

安定したサービス名に加え、onStartCommandの型、通知文言の複数アンカー、LocationRequestを受け取る呼び出し、同じクライアントの1引数解除、コールバック型の一致を組み合わせる。単に現在の `M2.a`・`U4.b` という短い名前で別バージョンを選ばない。一致が複数なら不採用とする。

APKの世代・解析ルール版・署名を含めて結果をモジュール自身の内部データへキャッシュする。通常起動では検証済み結果を読み、初回と更新後だけ再探索する。

## 残りの検証

- OFF直後にサービスが消えたのに位置要求だけ残るか、画面操作の許可された枠で確認する。
- 修正後はOFFで該当要求だけが消え、ONでは20秒・高精度の要求が復帰するか確認する。
- アプリの地図、現在地、着信ブロック、既存通知を妨げないことを確認する。
- 待機条件を揃えた消費比較は未測定。
